# 2. Mục tiêu tính năng

Cho phép người dùng xác thực tài khoản để truy cập vào hệ thống Community Forum bằng:

- Email + Password
- OAuth Login:

  - Google
  - Facebook

Đảm bảo:

- Bảo mật cao
- Chống brute force
- Quản lý session an toàn
- Hỗ trợ mở rộng 2FA trong tương lai

# 5. Business Rules

## BR-LOGIN-001

Người dùng chỉ được đăng nhập khi:

- Email tồn tại
- Password chính xác
- Tài khoản chưa bị khóa
- Tài khoản đã verify email (nếu bật policy)

---

## BR-LOGIN-002

Password phải được hash bằng:

- bcrypt
  hoặc
- argon2

Không lưu plain text password.

---

## BR-LOGIN-003

Giới hạn số lần login thất bại:

| Điều kiện     | Giá trị |
| ------------- | ------- |
| Max attempts  | 5 lần   |
| Lock duration | 15 phút |

---

## BR-LOGIN-004

Session phải:

- Secure cookie
- HttpOnly
- SameSite protection
- Regenerate session ID sau login thành công

---

## BR-LOGIN-005

Nếu bật 2FA:

- Sau bước password đúng → chuyển sang verify OTP
- Chưa tạo full authenticated session trước khi verify OTP thành công

---

## BR-LOGIN-006

OAuth login chỉ chấp nhận provider được cấu hình:

- Google
- Facebook

---

## BR-LOGIN-007

User bị disable/banned không được đăng nhập.

# 6. Luồng nghiệp vụ chính

## 6.1 Login bằng Email/Password

### Main Flow

```text
Guest
  ↓
Mở trang Login
  ↓
Nhập Email + Password
  ↓
System validate input
  ↓
Kiểm tra user tồn tại
  ↓
Kiểm tra password hash
  ↓
Kiểm tra trạng thái tài khoản
  ↓
Kiểm tra email verification
  ↓
Kiểm tra 2FA enabled?
  ├─ Yes → Verify OTP
  └─ No
        ↓
Tạo session/JWT
  ↓
Regenerate Session ID
  ↓
Redirect Dashboard/Home
```

---

## 6.2 Login thất bại

```text
Guest nhập sai password
  ↓
Tăng login_attempt
  ↓
Nếu vượt threshold:
    Lock account tạm thời
  ↓
Trả lỗi authentication
```

---

## 6.3 OAuth Login Flow

```text
Guest
  ↓
Click Login with Google/Facebook
  ↓
Redirect provider
  ↓
User authorize
  ↓
Provider callback
  ↓
Validate provider token
  ↓
Tìm user theo provider_id/email
  ↓
Nếu chưa tồn tại:
    tạo account mới
  ↓
Tạo session
  ↓
Redirect Home
```

# 7. Use Case Specification

## UC-LOGIN-001 — Đăng nhập Email/Password

| Mục            | Nội dung               |
| -------------- | ---------------------- |
| Use Case ID    | UC-LOGIN-001           |
| Actor          | Guest                  |
| Trigger        | User submit login form |
| Preconditions  | User đã có account     |
| Postconditions | User authenticated     |

### Basic Flow

1. User nhập email/password
2. System validate dữ liệu
3. System kiểm tra credential
4. System kiểm tra account status
5. System tạo authenticated session
6. Redirect về homepage/dashboard

### Alternative Flows

| Mã    | Mô tả               |
| ----- | ------------------- |
| AF-01 | Sai password        |
| AF-02 | Email không tồn tại |
| AF-03 | Account bị khóa     |
| AF-04 | Chưa verify email   |
| AF-05 | Yêu cầu 2FA         |

# 12. API Design

## POST /api/auth/login

### Request

```json
{
  "email": "user@example.com",
  "password": "secret",
  "remember_me": true
}
```

---

### Success Response

```json
{
  "success": true,
  "token": "jwt_token",
  "user": {
    "id": 1,
    "name": "John Doe",
    "role": "member"
  }
}
```

---

### Error Response

```json
{
  "success": false,
  "error_code": "AUTH_001",
  "message": "Invalid credentials"
}
```
